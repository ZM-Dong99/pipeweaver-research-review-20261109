# 售票状态机：独立模型对照

本目录保存公开 RTL-OPT `ticket_machine` 的一轮探索性对照。原始设计135行（含空行和注释），综合后28个单元，是小型控制逻辑，不代表大型工程电路。

实验准备完成后，用户批准本轮最多10次APINebula模型请求。两组各5次，不自动重试或补抽。实际调用数请查候选目录中的 `attempt.json` 和 `api_audit/request.json`；返回情况查 `generation.json`。不要把计划数量当作成功返回数。

两组公共提示完全相同：原始RTL、功能契约、复位/时钟/IO条件、工艺库名称、相同面积上限和输出格式。反馈组额外收到三条实际基线路径、WNS/TNS、实际FSM编码转换表和可核对的路径定位。

基线：WNS 9.30ns，TNS 0ns，映射面积252.7424 µm²，28单元。固定面积上限为278.01664000000005 µm²（基线110%），属于本轮实验规则。主选择要求WNS严格改善且TNS不退化；没有合格候选时保留原始RTL。超面积版本仍保留测量，不计主结果。

生成与评估分开：十个请求槽位处理结束后冻结 `candidate_manifest.json`，随后逐份对原始RTL运行源级等价、门级等价和STA。不能用本轮最好的候选反过来修改已冻结提示。

## 查看顺序

1. `protocol.json`：已冻结的条件、请求计划、哈希和限制。
2. `PREPARATION_AUDIT.json`：20项离线准备检查。
3. `AUTHORIZATION.json`：本轮十次授权，未存储密钥。
4. 各组/候选的 `api_audit/request.json`、`response.json`、`transport.json`：真实发送内容、返回内容和网络记录；请求审计省略Authorization头。
5. 各候选 `eda/result.json`、`formal.log`、`mapped_formal.log`、`mapping.log`、`sta.log`：功能与性能原始证据。
6. 全部完成后查看 `summary.json`、`AUDIT.json` 和 `INTERPRETATION.md`。文件未生成表示相应阶段尚未完成，不等于成功或失败。

## 边界

- Yosys对FSM重新编码；映射后的 `State[1]` 对应原始 `BILL30`，不是原始源码位号的直接延续。反馈明确列出了实际转换表。
- 同模型、相同请求次数和请求参数；反馈组输入更长，token用量不必相同。当前adapter无明确输出token上限，也无金额硬上限，必须报告实际用量。
- 公开代码，不是模型训练数据盲测；此前读过源码并做过基线验证，未发送专家参考RTL。
- 单个小型设计、每组5次，不能据此声称普遍优势或充分统计显著性。相同候选/网表要记录重复，不能当成不同结构。
- 请求模型ID是网关标签，不能由返回字段验证后台模型真实身份。
- SKY130HD TT、10ns理想时钟、固定IO负载，布局布线前；未进行功耗、寄生参数、多工艺角或物理签核。

本轮只针对固定默认参数ON=1、OFF=0、单次启动同步clear复位及之后任意定义输入序列证明。其他参数、异步行为、时钟域和延迟变化不在证明范围内。
